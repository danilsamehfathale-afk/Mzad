# مزاد game (Mazad Game)

لعبة مزادات أونلاين للاعبين اثنين: مزاد كرة قدم (35 بطاقة) ومزاد أنمي (40 بطاقة).
السيرفر (Node.js + Express + Socket.IO) هو المسؤول عن الوقت والمزايدات والميزانية والفائز.

## التشغيل على أندرويد (Termux)

1. ثبّت **Termux** (يفضل من F-Droid).
2. في Termux:
   ```
   pkg update
   pkg install nodejs unzip
   termux-setup-storage
   ```
3. فك الضغط وانسخ المشروع لمجلد Termux الرئيسي (مهم: متشغّلش `npm install` داخل مجلد التنزيلات لأن التخزين المشترك مش بيدعم الروابط الرمزية):
   ```
   cd ~/storage/downloads
   unzip mazad-game.zip -d ~
   cd ~/mazad-game
   ```
4. ثبّت الحزم (مرة واحدة، محتاج إنترنت):
   ```
   npm install
   ```
5. شغّل السيرفر:
   ```
   npm start
   ```
6. افتح المتصفح على `http://localhost:3000`.

لتجربة اللعبة بلاعبين: افتح تبويبين في المتصفح، أو استخدم جهازين على نفس الواي فاي
وافتح `http://<عنوان-الجهاز>:3000` (العنوان يظهر من أمر `ifconfig` أو `ip addr` في Termux).

## تعديل الملفات من Acode
في Acode: ☰ ← Open Folder ← Add a storage، واختر مجلد Termux لو ظهر عندك. لو ما ظهرش، عدّل الملفات في مجلد مشترك ثم انسخها لـ `~/mazad-game` بالأمر `cp -r`.

## الإعدادات
كل القيم في `server/config.js` (أو في ملف `.env` بنفس الأسماء، انسخ `.env.example`):
- `START_BUDGET` ميزانية كل لاعب، و`AUCTION_SECONDS` مدة المزايدة على كل بطاقة
- `EXTEND_WINDOW_SECONDS` / `EXTEND_SECONDS` تمديد الوقت عند المزايدة في اللحظات الأخيرة
- `MIN_BID_INCREMENT` أقل زيادة بين مزايدتين
- `MIN_OPENING_BID` أقل مبلغ لفتح المزايدة على أي بطاقة (مفيش سعر ابتدائي لكل بطاقة)
- `TIER_LEGEND` / `TIER_EPIC` / `TIER_RARE` حدود ألوان الندرة
- `MAX_ROOMS` و`CREATE_PER_MINUTE` و`JOIN_PER_MINUTE` حدود الحماية، و`TRUST_PROXY=1` لو السيرفر ورا proxy
قيم اللعبة (الميزانية والمدة والتمديد وأقل مبلغ للفتح) مقترحة وتحتاج موافقتك.

## قواعد مهمة في السيرفر
- أقصى مزايدة مسموحة للاعب = ميزانيته ناقص ما يلزم لشراء باقي خانات فريقه بحد فتح المزايدة (`MIN_OPENING_BID`) لكل خانة، عشان ما يعلقش بفريق ناقص. الواجهة بتعرض له الحد ده.
- لاعب انقطع وهو في غرفة الانتظار يتشال بعد `WAITING_GRACE_SECONDS` ويفضّي مكانه.
- فتح نفس الجلسة في تبويب تاني بيوقف التبويب القديم وبيعرض له زر "استخدم هذا التبويب".
- مفيش سعر ابتدائي لكل بطاقة: اللاعبين بيتبادلوا الدور في فتح المزايدة (البطاقة الأولى اللاعب 1 يفتحها بأي مبلغ، التانية اللاعب 2، وهكذا). اللاعب اللي عليه الدور بس هو اللي يقدر يفتح، وبعد الفتح الاتنين يزايدوا. لو صاحب الدور ما فتحش لحد ما الوقت يخلص، البطاقة ما تتباعش. ولو ميزانيته ما تكفي حد الفتح، الدور يروح للتاني.
- لو فريق لاعب اكتمل ولاعب تاني لسه ناقص، خانات الناقص بتتملى تلقائيًا ببطاقات عشوائية مجانية (من غير خصم ميزانية) ومينفعش يغيّرها، والمزاد بيخلص.
- الانسحاب أثناء المزاد معناه خسارة، والمنافس بيفوز.
- لو التقييم متساوي بين اللاعبين، يفوز صاحب الميزانية المتبقية الأكبر.
- السيرفر بيتقفل بشكل نظيف عند Ctrl+C، وبيسجّل الأحداث المهمة في الطرفية.

## البطاقات والصور
- البيانات في `data/football.json` و`data/anime.json`.
- صور اللاعبين من ويكيبيديا: `npm run images`
- صور شخصيات الأنمي من AniList: `npm run images:anime`
  (الأمرين مرة واحدة وإنت متصل بالإنترنت). الصور بتتحفظ محليًا في `public/images/` واللعبة بتستخدمها تلقائيًا. أي بطاقة ما اتحملتش بتفضل بالصورة البديلة (SVG)، والأمر بيطبع اللي فشل.
- لو البحث جاب شخصية غلط أو ما لقاش، حط الاسم اللي يناسب في حقل `wiki` (ويكيبيديا) أو `anilist` (AniList) للبطاقة في ملف JSON وشغّل الأمر تاني (أضف `-- --force` لإعادة تحميل الكل).
- الصور ملك أصحابها وتراخيصها مختلفة. مناسبة للتجربة الشخصية، ولو هتنشر اللعبة للعامة راجع الحقوق (رابط المصدر محفوظ في `imageSource`).
- التقييمات المكتوبة تقديرية وليست أرقامًا رسمية.

## الاختبار
`npm test` يشغّل اختبارات منطق المزاد ومعالجات الاتصال (باتصالات وهمية) والبطاقات وإدارة الغرف، من غير ما تحتاج شبكة. الاتصال الحقيقي عبر Socket.IO والواجهة في المتصفح لسه ما اتجرّبوش آليًا.

## ما هو غير موجود حاليًا
- حسابات المستخدمين وقاعدة البيانات: الغرف محفوظة في ذاكرة السيرفر فقط، وتختفي لو السيرفر اتقفل.
- النشر على الإنترنت: يحتاج خدمة استضافة (مرحلة النشر).
